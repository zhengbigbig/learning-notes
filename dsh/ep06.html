大家好，我是郑同学。EP05 讲了会话日志，日志里的 tool/result 是工具执行完落账的样子——这一篇往回退一步：模型发出 tool-call 之后、结果写回日志之前，中间发生了什么。dsh 把这条路拆成三段瀑布，一句话口诀，全文可对照：

pre 挡门，execute 缚线，post 裁果，guard 不翻案

拿一个真实场景贯穿：模型要执行 bash rm -rf /tmp/build 清理构建产物。这一次调用要闯三道关——权限关（该不该跑）、执行关（怎么跑）、结果关（结果算不算数）。

● ● ●

一、第一关 pre-execute：allow、deny、ask

裁决就三种（tools/src/index.ts:588）：

export type PreToolDecision =
  | { kind: 'allow' }
  | { kind: 'deny'; reason: string }
  | { kind: 'ask'; reason?: string }
 

对照场景读：查目录这种只读操作 → allow 放行；删系统目录 → deny 带原因拒绝；删 /tmp/build 这种可商量的 → ask 交给审批服务。挂了审批服务，弹窗等你点；没挂审批服务，ask 不是放行也不是挂死，而是降级成拒绝——模型拿到的报错还会区分「用户拒绝了」和「没有审批通道」两种「不」。

瀑布之外还有一道注册表自管的 guard（单调守卫）：

// 只能返回拒绝原因，没有放行结果
export type ToolGuard = (exec) => string | undefined
 

监听器顺序不可能把一道拒绝翻回成允许。职责分两层：权限的「软裁决」交给插件瀑布（可配置、可弹窗），安全底线交给单调 guard（沙箱策略走这条路，写死不翻案）。

● ● ●

二、第二关 execute：wrapper 只许换 signal

tools/execute 是环绕瀑布——超时、重试、指标包装都挂这里。超时插件的做法：给 exec.signal 换上一个带 deadline 的取消信号。但这里有个容易被忽略的漏洞：wrapper 换上的信号如果和调用方的原始信号断了链，你按停止就传不到工具本体了。dsh 的对策是熔合（tools/src/index.ts:1889）：

// 两个信号接到一个新控制器上
const fused = fuseToolSignals(state.callerSignal, wrapperSignal)
const signal = fused.signal
// 任一来源取消，熔合信号就取消
 

wrapper 想加超时可以，想甩掉调用方的取消权不行。还有一条硬规则：取消从不遗弃在途工作——已启动的工具会跑到落定，结果才标 ABORTED，不会凭空消失。

● ● ●

三、第三关 post-execute：接受、替换、拦截

工具跑完，结果不直接进日志，先过最终裁决（index.ts:593）：

| { kind: 'accept' }                        // 原样接受
| { kind: 'accept'; content }               // 替换投影
| { kind: 'block'; feedback }               // 拦成错误+纠正反馈
 

真实挂件这么用：dsh-compaction-tool-pruner 在这关把超长工具结果修剪到预算内；dsh-spill-policy 把巨型文本替换成「预览 + 定位符」。block 的 feedback 是给模型的纠正文本——模型下一步能看到自己错在哪。三种裁决都能附 additionalContexts（额外上下文，回注队列，EP04 讲过）。

● ● ●

对照：一次调用的完整旅程

关口裁决/动作场景对照
pre-executeallow / deny / ask（缺审批=拒）删 /tmp/build → ask → 弹窗
guard只能拒，不能翻案沙箱策略兜底
execute包装执行，signal 被熔合超时插件给删除加 30s 上限
post-execute接受 / 替换 / block输出太长 → 修剪后接受
tools/result只读观测冻结结果遥测、日志

还有一个作用域细节：三段瀑布都做了作用域过滤——通过 agent.ctx 注册的监听器只收到自己 agent 的调用；而 tools/change（工具集变更）特意不过滤，全局广播。该过滤的过滤、该广播的广播，事件契约写在 JSDoc 里不靠猜。

收尾重复口诀：pre 挡门，execute 缚线，post 裁果，guard 不翻案。三段瀑布加上 EP04 的调度池、EP05 的落账，工具这条线就完整了。下一篇 EP07 讲 LLM seam：适配器注册表怎么做到「全成或全不生效」，以及 llm-pi-ai 那个挂载即休眠、settings 一段就活的多提供方双子。
