大家好我是郑同学。EP00 立了论断：dsh 的 Agent Loop 是插件。这一篇进它的实现——packages/core/agent-loop/src/agent.ts，496 行，把 turn 和 step 的双层循环逐段读掉。读完你会发现它和 EP01 的五种事件模式、EP02 的插件行清单严丝合缝：循环是插件，插件用事件，事件有契约。

先立骨架。整个文件的心脏是三个函数：kick() 驱动、turn() 管任务生命周期、step() 管一次模型请求。关系一句话：kick 踢一脚，turn 转一圈，step 走一步。

● ● ●

kick()：一脚启动的驱动器

入口在 agent.ts:210，短到可以全文贴出：

private async kick(): Promise<void> {
  while (await this.turn()) {}
}
 

turn() 返回 boolean——还有下一个 turn 要跑就返回 true，kick 继续转；没有就返回 false，驱动器停下。驱动器自己没有任何业务逻辑，它只负责「还有活就继续干」。唤醒它的时机是 inbox 有新消息到达（EP00 提过：有些消息立即唤醒，注入的上下文留在 inbox 里等另一条消息）。

turn()：一个任务的生命周期

turn() 在 agent.ts:246。剥掉防御性代码后主干是这样：

private async turn(): Promise<boolean> {
  const turn = phase.turn + 1
  this.session.append('turn/start', { turn })
  let turnEnds: TurnEndReason | null = null
  let target: InboxTarget = 'next-turn'
  while (true) {
    signal.throwIfAborted()
    const step = phase.step + 1
    const decision = await this.preStep(target, { turn, step })
    if (decision.kind === 'reject') {
      turnEnds = { kind: 'blocked' }
      return false
    }
    if (turnEnds && decision.messages.length === 0) break
    // 首次领取被改写为空：关闭一个不含步骤的持久轮次
    if (phase.step === 0 && decision.messages.length === 0) {
      turnEnds = { kind: 'completed' }
      return false
    }
    this.session.append('step/start', { turn, step })
    try {
      for (const message of decision.messages) {
        this.session.append('user/message', message, { surfaceOp: 'append' })
      }
      const stepEnd = await this.step(decision.assembly)
      // max-tokens 粘性：后续正常完成的步骤
      // 不能把 turn 的结论降级
      if (turnEnds === null || turnEnds.kind !== 'max-tokens') turnEnds = stepEnd
    } finally {
      this.session.append('step/end', { turn, step })
    }
    if (turnEnds && this.inbox.nextStep.length === 0) {
      await this.dispatch.serial('agent/turn-stopping', { turn, signal })
    }
    if (turnEnds && this.inbox.nextStep.length === 0) break
    target = 'next-step'
  }
  // ...turn/end 收尾
}
 

五个细节值得停。

preStep 领取有裁决权。 每步先问 agent/pre-step 瀑布要消息，监听器可以改写已领取的消息，也可以直接拒绝。架构文档特意说明：首次领取被拒绝或被改写为空时，仍会关闭一个不含步骤的持久轮次——日志会记录这次尝试，不装作没发生。

inbox 是双队列。 next-turn 队列的消息立即唤醒驱动器开新 turn；next-step 队列（注入的上下文）留在原地，等另一个 turn 跑到「turnEnds 且 nextStep 队列空」才真正结束。循环出口连续判两次 nextStep.length === 0，中间夹一个 agent/turn-stopping——这是 serial 事件，监听器可以在最后一刻再塞活进来，第二次检查确认没有新活才放行退出。

max-tokens 有粘性。 一旦某步撞了输出上限，turnEnds 锁定为 max-tokens，后面即使有正常完成的步骤也不覆盖——源码注释原话：「max-tokens stays sticky: a later completed step must not downgrade the turn outcome」。坏消息不因为后面有好消息就变成没发生。

每个动作都写日志。 turn/start、step/start、user/message、step/end 全部 append 进 EP04 要拆的会话日志。循环运行的可观测性不是外挂的，是循环本身的副产物。

blocked 与 completed 语义分开。 被拒绝叫 blocked，没活干叫 completed，撞上限叫 max-tokens——终态是枚举不是布尔，日志里能看出「怎么结束的」。

step()：一次模型请求的完整 anatomy

step() 在 agent.ts:332，主干四段：

private async step(assembly: PromptAssembly): Promise<StepEndReason | null> {
  const system = renderPrompt(assembly)
  while (true) {
    const { request, preparedCall } = await this.buildRequest(
      turn, step, assembly.tools, system, this.session.deriveMessages(), signal,
    )
    const assembler = new BlockAssembler()
    const stream = preparedCall?.stream(request) ?? this.loopCtx.llm.stream(request)
    for await (const chunk of stream) {
      signal.throwIfAborted()
      chunkSeqs.push(this.session.append('assistant/chunk', { turn, step, chunk }).seq)
      assembler.push(chunk)
    }
    const finish = assembler.finish
    if (finish.kind === 'error' || finish.kind === 'aborted') {
      const action = await this.dispatch.waterfall(
        'agent/request-error', { /* ... */ },
        () => Promise.resolve<RequestErrorAction>(undefined),
      )
      if (action?.kind !== 'retry') {
        throw new LlmError(finish.failure.message, finish.failure.code, finish.failure)
      }
      continue
    }
    const message = createAssistantMessage({ /* blocks, source */ })
    this.session.append('assistant/message', { turn, step, message, usage })
    if (finish.kind === 'max-tokens') return { kind: 'max-tokens' }
    const toolCalls = message.content.filter(block => block.type === 'tool-call')
    if (toolCalls.length === 0) return { kind: 'completed' }
    const { concluded } = await executeToolCalls(
      this.loopCtx, turn, step, toolCalls, signal, /* splice 回注 */ ,
    )
    return concluded ? { kind: 'completed' } : null
  }
}
 

四段各一句话。组装：renderPrompt 渲染系统提示词（EP07 的产出物），deriveMessages 从日志投影模型历史（EP04 的产出物），buildRequest 冻结请求并绑定位它默认值的适配器注册（EP06 的机制）。流式：每个 chunk 先入日志再进 BlockAssembler——先记账再消费，UI 打字机效果来自日志回放而不是直连模型。容错：error/aborted 走 agent/request-error 瀑布，监听器可以返回 retry 让整个 while 重来一次；不 retry 就抛 LlmError。裁决：assistant/message 入库后过滤 tool-call 块——没有工具调用返回 completed，本 turn 收工；有就 executeToolCalls（EP05 的三段瀑布在里面），工具结果回注 next-step 队列，返回 null 表示还有下一步要跑。

注意 while(true) 只包住「请求-失败-重试」这一层，不是外层循环——重试的是请求，不是步骤。

● ● ●

循环与世界的全部接口

回头看 step 依赖的外部服务：llm.stream（模型）、session.append/deriveMessages（日志）、dispatch.waterfall/serial（事件）、executeToolCalls（工具）、inbox（输入）。五个接口全是 EP01 说的 ctx 服务或事件。循环是编排者，不是执行者——这 就是它能作为插件存在的原因：抽掉任何一环换实现，循环代码不动。
