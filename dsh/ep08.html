大家好，我是郑同学。EP07 讲了请求的出站接缝，这一篇看请求的头部：系统提示词。dsh 里它不是一段写死的文本，而是一个每一步组装一次的段注册表——工具引导、部署 persona、harness 身份各自是一个段，每次模型调用前按顺序拼起来。口诀：

段有次序，名可遮蔽，词必严插，序可显排，缓存写契约

为什么每步组装而不是一会话一次：段的文本可以是函数——工具目录会变（热装卸）、变量会变（当前模型、cwd）。组装的时机跟着请求走，请求看到什么由组装那一刻的注册表决定。

● ● ●

一、一条数轴：-100 身份、0 号 persona、100+ 工具引导

段的形状（system-prompt/src/index.ts:53）：

export interface PromptSection {
  readonly name: string    // 同名重复注册 → 抛错
  readonly order: number   // -100 harness 身份 / 0 persona / 100-199 工具引导
  readonly text: string | ((context) => string)  // 静态文本或每次组装求值的函数
}
 

服务自带的两个段，真实代码（index.ts:353）：

this.section({
  name: 'harness:identity', order: -100,
  text: 'You are an AI agent powered by DeepSeek Harness.'
})
this.section({
  name: PERSONA_SECTION, order: 0,   // 'deployment:persona'
  text: config.persona ?? ''
})
 

段的顺序规范化了「插件加载时序」这个偶然产物：不管插件先挂后挂，最终提示词的段落顺序只由 order 决定，确定性不依赖加载顺序。

同名遮蔽和 EP06 的作用域一脉相承：通过 agent.ctx 注册的段只属于那个 agent，同名时遮蔽全局段。最典型的用法是 persona 替换——PERSONA_SECTION 常量被特意导出，就是让 agent preset 的作者能对准这个槽位：两边叫同一个名字，替换才不会变成重复。

● ● ●

二、变量与严格插值

persona 模板里可以写「你在 {{cwd}} 下工作，当前模型 {{model}}」。三个变量由 agent loop 注册：

variable('provider', ctx => ctx.agent?.options.provider)
variable('model',    ctx => ctx.agent?.options.model)
variable('cwd',      ctx => ctx.agent?.session.header.cwd)
 

每个 agent 每次组装各自求值。插值是严格模式：未知变量抛异常、已注册但本次无值抛异常——宁可不发请求，不发一条带 {{model}} 原文的提示词。

● ● ●

三、toolOrder 与 complete：两个显式开关

工具 schema 的顺序也是注册表管的：toolOrder 是一个名字列表，必须恰好含一个 标记——已列工具按列表位置排，未列工具按字典序插进标记处；不配置就整体字典序（code-unit 比较，在任何机器上顺序都一样）。

还有一个 complete: true 的段类型：声明自己是完整提示词。组装照常跑完（工具、变量都解析），然后这个段被恢复为唯一段。两个 complete 段同时存在，组装直接拒绝——「谁是完整提示词」只能有一个答案。

● ● ●

四、每步组装 vs KV Cache：把张力写成契约

每步重新组装，最直接的质疑是缓存：系统提示词是请求前缀，前缀变了缓存就得重算。dsh 没有回避——每个包的 README 里都有一节「KV Cache 影响」：只要身份、persona、变量、段文本与顺序的渲染完全相同，前缀就保持稳定；任何变更从第一个变化的 token 起失效。

实际运行是自洽的：-100 身份是常量；persona 是配置不随步变；工具目录除非装卸否则稳定；模型变量变了意味着路由变了，缓存本来就该失效。每步组装的成本是一次确定性检查，收益是任何注册表变化下一次请求立刻生效——热装卸工具、切 persona，全都不用重启。

● ● ●

对照：这层的五个机制

机制语义
section()有序段贡献；-100 / 0 / 100+ 的数轴约定
同名遮蔽agent.ctx 段遮蔽全局；persona 槽靠同名替换
变量插值{{model}}/{{cwd}}/{{provider}}，严格模式失败抛错
toolOrder显式列表 + 标记
KV Cache 契约每包 README 公开「什么会打碎前缀」
