大家好我是郑同学。前面拆 CC 和拆 Pi，拆的都是终端里的 harness。这一次换个视角——桌面端。为什么一个 agent 要做桌面应用？桌面壳和 agent 本体怎么分工？这一篇用 Hermes Desktop（Nous Research 出品，MIT 协议，230K star）开刀，把它的三层架构拆开看。

先说结论：Hermes 桌面端最值得学的不是界面，而是它"一次实现、三个前端"的架构决策。桌面、网页、终端三个界面共享同一个 Python agent 后端，谁都不是亲儿子，谁也离不开谁。

● ● ●

先从终端看起：屏幕和活儿是怎么分家的

ui-tui 的 README 第一段就是架构宣言（ui-tui/README.md）：

React + Ink terminal UI for Hermes. TypeScript owns the screen.
Python owns sessions, tools, model calls, and most command logic.
 

翻译过来：TypeScript 只管屏幕渲染，会话、工具、模型调用、命令逻辑全在 Python 侧。它启动时的进程关系是（ui-tui/src/gatewayClient.ts:795 行的实现）：

● ● ●

再看桌面端：拉起的是同一个网关

桌面端的 Electron 主进程里有一个 49 行的文件，注释把整个策略讲透了（apps/desktop/electron/backend-command.ts）：

// apps/desktop/electron/backend-command.ts（真实源码节选）
// Backend subcommand routing for the desktop-managed Hermes process.
//
// The desktop app launches its own headless backend via `hermes serve` —
// it must NEVER depend on or launch the browser `dashboard`. But `serve`
// is a newer subcommand: a runtime that predates it ... only knows
// `dashboard --no-open`. To avoid bricking those users mid-upgrade we
// detect whether the resolved runtime understands `serve` and, only when
// it does not, fall back to the legacy `dashboard --no-open` invocation.
// Both produce the exact same headless gateway.
 
export function serveBackendArgs(profile?: string) {
  const head = profile ? ['--profile', profile] : []
  return [...head, 'serve', '--host', '127.0.0.1', '--port', '0']
}
 
export function dashboardFallbackArgs(args) {
  const i = args.indexOf('serve')
  if (i === -1) return args.slice()
  return [...args.slice(0, i), 'dashboard', '--no-open', ...args.slice(i + 1)]
}
 

三个信息量极大的细节：

桌面端的后端就是 hermes serve——无头网关，绑 127.0.0.1，端口 0 表示让系统随机分配（避免端口冲突），拿到实际端口后再连。桌面端没有专属后端。

版本兼容回退。serve 是新子命令，老版本 runtime 只认识 dashboard --no-open。桌面端会先探测 runtime 源码里有没有 add_parser("serve"（正则精确匹配，注释特意说明为什么不会把 "server" 误判成 "serve"），没有就回退老命令。升级路上不 brick 用户，这是一个桌面壳的基本修养。

注释里的 NEVER 大写：桌面端绝不允许拉起浏览器版 dashboard。三个前端各有各的入口，互不越界。

最后看网关：桌面端只是"又一个渠道"

gateway/platforms/ 目录下的文件列表本身就是架构说明：

├── base.py            317KB  ← 渠道基类
├── weixin.py           94KB  ← 微信
├── whatsapp_cloud.py   89KB  ← WhatsApp
├── signal.py           70KB  ← Signal

api_server.py 和 weixin.py 平级。也就是说，在 Hermes 的世界观里，桌面端连进来的 WebSocket 网关，和微信渠道、WhatsApp 渠道是同一层的东西——都是一个 platform。桌面端没有特权，它就是众多前端渠道之一。

api_server.py 有 7602 行，启动段（gateway/platforms/api_server.py:7392-7445）里还有一个值得抄的工程细节：

# gateway/platforms/api_server.py（真实源码节选）
if not self._api_key_passes_startup_guard():
    # A rejected API_SERVER_KEY is a configuration error, not a
    # transient blip — the key will not become valid on its own. A
    # bare ``return False`` makes the reconnect watcher ... loop
    # forever at the backoff cap, re-instantiating the adapter
    # (and its ResponseStore sqlite connection) every retry
    # (#38803: ~501 leaked connections / 1002 fds over 2.5 days
    # until EMFILE took the whole gateway down).
    self._set_fatal_error("api_server_key_invalid", ..., retryable=False)
    return False
 

API key 配错是配置错误，不是网络抖动。如果当成可重试错误，重连 watcher 会按退避上限无限重试，每次重新实例化 adapter 和它的 sqlite 连接——注释里记录了真实事故编号：2.5 天泄漏 501 个连接、1002 个文件描述符，直到 EMFILE 把整个网关打挂。所以配置错误必须标记 retryable=False，直接踢出重连队列。

● ● ●

三层各自的生存哲学

拆到这里，每层的职责边界已经清晰：

前端层：apps/desktop（694 个 TS/TSX）、web（108 个文件）、ui-tui。React 写三遍，但业务逻辑零重复。桌面端主进程还要干脏活——更新热重建、窗口管理、跨平台兼容（Windows 子进程、WSL 剪贴板），这些在 electron/ 目录下有 60+ 个模块，EP02 专门拆。

网关层：gateway/ 90 个 py。所有前端、所有聊天渠道在这里汇合，统一消息模型往外分发。渠道差异（微信的媒体格式、Signal 的限流）被吸收在各自的适配器里。

本体层：agent/ 138 个 py。conversation_loop 驱动 agent 循环，工具执行、上下文引擎、记忆管理、技能加载全在这里。它不知道前端是谁，甚至不知道有没有前端。

这个分法换来一个直接收益：公众号读者里如果有人想给 Hermes 写个新前端——比如一个 IDE 插件——不需要碰 agent 一行代码，实现 gateway 协议就够了。三层里每一层都可以独立替换，这就是"一次实现、三个前端"的底气。

● ● ●

为什么值得这么分

三进程分离的代价是复杂度——光是"前端怎么找到 Python 解释器"就要写六级回退，"新子命令老 runtime 不认识"要写探测回退。换来的是同一个 agent 同时服务桌面、网页、终端、微信、WhatsApp：新前端零成本接入，agent 本体零改动。

下一篇 EP02 进桌面壳内部：Electron 主进程 60+ 模块怎么管一个外部语言后端——启动探测、健康检查、崩溃恢复、自更新热重建，桌面端全家的脏活清单。

● ● ●

小结

你看到的实际在哪层源码位置
桌面窗口前端层apps/desktop（694 TS/TSX）
网页远程前端层web/（108 文件）
终端界面前端层ui-tui（React+Ink）
WebSocket 网关网关层gateway/platforms/api_server.py
微信/WhatsApp网关层（平级渠道）gateway/platforms/weixin.py 等
agent 循环本体层agent/conversation_loop.py

口诀：屏幕归前端，汇合在网关，本体不知道谁在连。桌面端不是特殊公民，是协议面前人人平等的第一证据。
