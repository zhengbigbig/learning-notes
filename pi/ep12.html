5 个层，从下往上：

协议层（types.ts + survival/events.ts）：定义 Agent 的所有数据结构——消息类型、事件类型、StopReason。一切从这里开始。

流式与模型层（event-stream.ts + provider-adapter.ts + scripted-model.ts）：EventStream 三态闸门解决异步流式，Provider Adapter 适配各家 API，ScriptedModel 把测试变成可执行规格。

工具层（tool.ts + coding-tools.ts）：工具契约管线和四个真实编码工具。原子写、批量替换、工作目录隔离。

循环与状态层（agent-loop.ts + agent.ts）：Agent Loop 把一切串成 for 循环，Agent 类用 reducer 管理状态。

持久化与组装层（session.ts + context.ts + resources.ts + composition.ts）：会话树持久化、上下文压缩、资源扩展、最终组装。

Pi vs CC：同一个循环，两种工程取舍

CC（learn-claude-code）是前面学过的 Python 教学版 Agent。CC 全部 30 行代码——while True 循环，调模型、执行工具、喂回去。

维度CC (Python)Pi (TypeScript)
语言动态类型tagged union + never 穷尽检查
模型接入直接调 Anthropic SDK多 Provider 适配器层
流式无（同步阻塞）SSE 流式 + EventStream
工具系统dict + run_bashRegistry + validator + executor
循环while True + stop_reasonfor steps 1..32 + StopReason 联合类型
并发工具串行Promise.all 并发
状态全局 history 数组reducer + 订阅 + 取消
持久化无JSONL 会话树 + commit marker
上下文管理无预算投影 + compaction entry
扩展无skill 按需激活 + hook
测试无ScriptedModel + held-out capstone

CC 胜在直接——30 行代码跑通概念，你立刻看到 Agent 在工作。Pi 胜在严谨——5009 行把概念变成生产系统，每一步都有类型约束、错误归一化、持久化保证。

两套代码教的是同一件事：Agent Loop 怎么从零搭起来。但工程取舍完全不同。

几个设计值得记住

回头看整个系列，有几个设计特别值得记住：

call id 因果配对（EP01）：两个 Set 登记簿，悬空即报错。从第一天就建立的不变量，贯穿整个系列。

EventStream 三态（EP02）：queue（事件先到）、waiting（消费者先等）、done（终态闸门）。「终态之后的 push 不得制造第二个事实」。

ScriptedModel（EP03）：不是 mock，是可执行规格。把预期的多轮行为写成可测试的 Model 实现。

并发工具执行（EP05）：Promise.all——多个工具同时跑，完成顺序和 transcript 顺序可以不同。

原子写 + MutationQueue（EP06）：先写 temp 再 rename，对同一个文件的写操作串行化。

reducer 纯函数（EP07）：AgentEvent → AgentState，状态变化可预测、可重放。

换行是 commit marker（EP08）：半行 JSON 在崩溃恢复时被丢弃——数据不可变，变更靠追加。

不动历史只重建投影（EP09）：历史消息一条不删，给模型看的是压缩后的上下文投影。

按需激活 + 原子注册（EP10）：skill 只收集 metadata，用到才读全文；扩展注册失败不留残骸。

composition root 只接线（EP11）：六步接线，不重新实现，所有零件通过接口连接。
