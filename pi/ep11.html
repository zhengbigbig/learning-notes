createRuntime：六步接线

课程把这步叫做 composition root——依赖注入的唯一入口。源码第 317 行：

// composition.ts:317-353
export async function createRuntime(
  config: RuntimeConfig,
  deps: RuntimeDeps,
): Promise<Runtime> {
  // 1. 从 session 读取已有历史
  const entries = await deps.session.entries();
  // 2. 从叶子节点恢复当前对话路径
  const initialPath = validateSessionSelection(entries, config.activeLeafId);
  const initialMessages = messagesIn(initialPath);
  // 3. 拼接 system prompt（用户配置 + 资源上下文）
  const systemPrompt = combinedSystemPrompt(config.systemPrompt, deps.resources);
  // 4. 包一层 context 投影 model
  let runtime!: RuntimeImpl;
  const model = createContextProjectingModel(
    deps.model,
    { systemPrompt, context: config.context },
    () => runtime.contextSnapshot(),
  );
  // 5. 工具执行器（可被 hook 拦截）
  const coreExecutor: ToolExecutor = (call, context) =>
    executeToolCall(call, deps.tools, context);
  const toolExecutor = deps.extensionHost
    ? deps.extensionHost.wrapExecutor(coreExecutor)
    : coreExecutor;
  // 6. 创建有状态 Agent
  const agent = new Agent({ model, tools: deps.tools, toolExecutor,
    initialMessages, systemPrompt, maxSteps: config.maxSteps });
  runtime = new RuntimeImpl(agent, initialPath, deps);
  return runtime;
}
 

六步，每步对应前面讲过的一个源码文件：

  •  第 1-2 步：session.ts——从 JSONL 会话树恢复历史
  •  第 3 步：resources.ts——拼接 system prompt + 资源上下文
  •  第 4 步：context.ts——上下文投影包装
  •  第 5 步：tool.ts + resources.ts——工具执行 + hook 拦截
  •  第 6 步：agent.ts + agent-loop.ts——有状态 Agent

所有零件通过接口连接，不直接依赖具体实现。

createContextProjectingModel：上下文投影

课程特别强调了这层——Agent 内部保留完整的 canonical transcript，但每次调模型前，把超过预算的旧消息压缩成摘要。

// composition.ts:148-177
export function createContextProjectingModel(
  inner: Model,
  config: Pick<RuntimeConfig, "systemPrompt" | "context">,
  getSnapshot: () => ContextProjectionSnapshot,
): Model {
  return {
    stream(context, options = {}) {
      const snapshot = getSnapshot();
      const projected = buildContext(
        temporaryEntries(snapshot, context.messages),
        {
          maxTokens: config.context.total,
          reservedOutput: config.context.reservedOutput,
          safetyMargin: config.context.safetyMargin,
          systemPrompt: config.systemPrompt,
          estimateTokens: config.context.estimateTokens,
        },
      );
      const request: AgentContext = {
        systemPrompt: projected.systemPrompt,
        messages: structuredClone(projected.messages),
        tools:
          context.tools === undefined
            ? undefined
            : structuredClone(context.tools),
      };
      return inner.stream(request, { signal: options.signal });
    },
  };
}
 

模型拿到的永远是压缩后的上下文，但 Agent 内部的完整 transcript 一条不少。temporaryEntries 把未落盘的消息临时接到 activePath 上，buildContext 做预算投影。

RuntimeImpl.prompt：一条消息的完整旅程

// composition.ts:248-271
prompt(value: string): Promise<AgentRunResult> {
  if (this.disposed) return Promise.reject(new Error("Runtime 已 dispose"));
  if (this.poisoned) return Promise.reject(this.poisonCause);
 
  const operation = this.operationTail.then(async () => {
    this.assertHealthy();
    const beforeCount = this.agent.getState().messages.length;
    const result = await this.agent.prompt(value);
    const suffix = result.messages.slice(beforeCount);
    await this.persist(suffix);
    return structuredClone(result);
  });
  this.operationTail = operation.then(() => undefined, () => undefined);
  return operation;
}
 

四步：

  1. 01调 agent.prompt(value)——触发 Agent Loop
  2. 02取出新增的消息（suffix）
  3. 03持久化到 session
  4. 04返回深拷贝结果

operationTail 串行化——每个 prompt 排队执行，不会并发。

persist：逐条 append 到会话树

// composition.ts:222-246
private async persist(messages: readonly AgentMessage[]): Promise<void> {
  let parentId = this.activeLeafId;
  for (const message of messages) {
    try {
      const entry: MessageSessionEntry = {
        id: this.deps.createId(),
        parentId,
        timestamp: this.deps.now(),
        type: "message",
        message: structuredClone(message),
      };
      await this.session.append(entry);
      this.activePath.push(structuredClone(entry));
      this.persistedMessageCount += 1;
      this.activeLeafId = entry.id;
      parentId = entry.id;
    } catch (error) {
      this.poisoned = true;
      this.poisonCause = error;
      throw error;
    }
  }
}
 

每条消息逐条 append，每条带 parentId 指向上一条——会话树的节点链接。一条 append 失败，整个 Runtime 进 poison 状态，后续所有操作直接拒绝。

三种 mode

课程最后教了 Runtime 的三种运行模式：

// composition.ts:365-389
export async function runMode(
  runtime: Runtime,
  mode: RuntimeMode,
  prompt: string,
  io: ModeIO,
): Promise<AgentRunResult> {
  const result = await runtime.prompt(prompt);
  const output =
    mode === "json"
      ? ${JSON.stringify({ reason: result.reason, steps: result.steps, messages: result.messages })}\n
      : finalAssistantText(result);
  await io.write(output);
  return structuredClone(result);
}
 

mode 不拥有 Agent 或 persistence，只负责选输出编码。interactive 和 print 走同一条路径（取最后一条 assistant 消息的文本），json 输出结构化结果。三个 mode 调的 runtime.prompt 完全一样，区别只在最后输出怎么格式化。

这一节学了什么

课程 Checkpoint 13 教的：composition root 只接线，不重新实现。在 Pi 源码里，createRuntime 六步接线——session 恢复、system prompt 拼接、context 投影、工具执行器、有状态 Agent、RuntimeImpl。每一步对应一个前面讲过的源码文件。

所有零件通过接口连接，通过依赖注入传入，可替换、可测试。这是整个系列的最后一层——前面 10 章学的每个零件，在这里拧成一台完整的机器。
